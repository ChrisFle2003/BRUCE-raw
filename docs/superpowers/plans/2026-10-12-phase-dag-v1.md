# PhaseDagV1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Einen kleinen, seriellen und vollständig replaybaren Phase-DAG-Referenzkern mit festen Fixture-Adaptern liefern.

**Architecture:** Der neue Kern lebt ausschließlich unter `bruce/phase_dag`. Er validiert zuerst eine kanonische, azyklische Spec, führt dann zwei intern registrierte Fixture-Adapter in deterministischer Reihenfolge aus und verifiziert gespeicherte Läufe durch Neu-Ausführung. Bestehende Application-Sessions, CLI-Befehle, Mods und Gates bleiben unverändert.

**Tech Stack:** C++20, STL, vorhandenes OpenSSL-gestütztes `bruce::sha256`, CMake, Ninja und CTest.

**Spec:** `docs/superpowers/specs/2026-10-12-phase-dag-v1-design.md`

## Global Constraints

- Der einzige neue öffentliche Vertrag ist `phase-dag-v1`; das Bundle beginnt exakt mit `BRUCE_PHASE_DAG_RUN_V1`.
- IDs sind 1..64 ASCII-Zeichen aus `[A-Za-z0-9_.-]`; Nodes und Dependencies sind byteweise sortiert und eindeutig.
- V1 akzeptiert 1..16 Nodes, höchstens 15 Dependencies je Node, höchstens 64 Kanten, höchstens 65.536 Request-/Output-/Evidencebytes, `max_started_nodes` 0..16, `max_receipt_bytes` 1..262.144 und `max_trace_entries` 2..512.
- V1 ist seriell, azyklisch und besitzt ausschließlich interne Fixture-Adapter. Keine dynamischen Plugins, Dateien, Netzwerkzugriffe, NanoCell-, Language-, CLI-, ApplicationTask-, Session-, Gate-, Experience-, GPU- oder Parallelitätsintegration.
- `READY` ist ein Scheduler-Receipt; ein Adapteroutput kann unabhängig davon `COMPLETE`, `INCOMPLETE` oder `REJECTED` sein. Kein DAG-Status stärkt eine fachliche Aussage oder ein Gate.
- Vor jedem Adapterstart haben globaler Control und Budget Vorrang. Ein globaler Stopp macht alle unentschiedenen Nodes `CANCELLED`; ein lokaler Fehler blockiert nur Nachfolger.
- Digests dienen der Integrität, nicht der menschlichen Autorisierung. Exporte und Persistenz sind nicht Teil von V1.
- Keine neuen Drittanbieterabhängigkeiten. Alle Produktionsquellen werden mit `-Wall -Wextra -Werror` gebaut.
- Die vollständige Prüfung nutzt den im Repository vorgegebenen `scripts/with-host-deps.sh`-Pfad; wenn dessen lokales Dependency-Bundle fehlt, ist das als Umgebungsblocker zu dokumentieren, nicht durch Paketinstallation zu umgehen.

## Review Focus

- **Unkanonische Graphen:** Unsortierte oder doppelte Nodes/Dependencies, Selbstkanten und Zyklen dürfen vor jedem Fixture-Aufruf scheitern.
- **Statusverwechslung:** `INCOMPLETE` und `REJECTED` müssen Adapteroutput bleiben und trotzdem einen `READY`-Receipt erzeugen.
- **Stopppriorität:** Bei Control oder Budget dürfen noch offene Nodes nicht fälschlich `BLOCKED` werden und keine Adapterausgabe freigeben.
- **Receiptgrößenlimit:** Überschreitet ein Adapteroutput die Receiptgrenze, darf kein partieller `READY`-Output sichtbar bleiben.
- **Neu gehashte Manipulation:** Ein neu berechneter äußerer Digest darf veränderte Inputs, Receipts, Outcomes oder Trace nicht legitimieren.

```cpp
namespace bruce {
struct PhaseInputRefV1 {
    std::string producer_node_id, producer_adapter_id, producer_adapter_version;
    std::string producer_status, producer_output_digest, producer_evidence_digest;
};
enum class PhaseOutputStatusV1 { complete, incomplete, rejected };
struct PhaseOutputRefV1 {
    std::string output_version{"phase-output-v1"};
    PhaseOutputStatusV1 status;
    std::string output_bytes, output_digest, evidence_bytes, evidence_digest, claim_scope;
};
enum class PhaseReceiptOutcomeV1 { ready, blocked, failed, cancelled };
struct PhaseReceiptV1 {
    std::string node_id, adapter_id, adapter_version, request_digest;
    std::vector<PhaseInputRefV1> input_refs;
    PhaseReceiptOutcomeV1 outcome;
    std::optional<PhaseOutputRefV1> output;
    std::string failure_code;
};
struct PhaseDagControlV1 { std::function<bool()> cancelled; };
struct PhaseDagRunV1 { PhaseDagSpecV1 spec; std::vector<PhaseReceiptV1> receipts; std::vector<PhaseTraceEntryV1> trace; };
PhaseDagRunV1 execute_phase_dag_v1(const PhaseDagSpecV1&, const PhaseDagControlV1& = {});
}
```

- [x] **Step 1: Write failing scheduler tests for successful and partial outputs**

  Define a source fixture with requests `C:<bytes>`, `I:<bytes>`, `R:<bytes>` and `F`; define a join fixture with an empty request. Test that sources `a`, `b` and join `c` start in that order and that `c` receives inputs in `a`, `b` order. Prove that `I:x` and `R:x` produce `READY` receipts with the corresponding embedded output status.

- [x] **Step 2: Write failure, dependency, budget and cancellation tests**

  Test failing `a`, dependent `b` and independent `c`: outcomes are `FAILED`, `BLOCKED`, `READY`. Test `max_started_nodes == 0` and a callback that stops before `b`: all still-unresolved nodes are `CANCELLED`. Test receipt overflow: the producing node becomes `FAILED` with `DagReceiptBudgetExceeded`, exposes no output and blocks dependents.

- [x] **Step 3: Implement the private fixture registry and serial scheduler**

  Use a private closed dispatcher over exactly `fixture-source-v1` and `fixture-join-v1`. Execute the lexicographically smallest ready node. Copy requests and input references before calling the adapter. Translate adapter exceptions to `FAILED`; retain independent scheduling. Validate output/evidence digests and receipt limits before exposing `READY`.

  Run: `scripts/with-host-deps.sh cmake --build /tmp/bruce-phase-dag --target bruce_phase_dag_tests` and the focused `ctest` command from Task 1.

  Expected: PASS; exactly one receipt exists for each node, global stops dominate local dependency logic, and `INCOMPLETE`/`REJECTED` remain adapter states.
